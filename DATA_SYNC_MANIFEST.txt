## Why this file exists

`models/` (trained checkpoints) and `outputs/` (metrics gzips, optuna DBs)
are gitignored -- they never come through `git clone`/`git pull`. They were
copied to the local machine manually (scp/rsync) outside of git. This file
is the source-of-truth listing from the cluster at copy time, so a
verification pass can confirm nothing was dropped or corrupted in transit.

## How to verify (instructions for whichever Claude session reads this)

1. Confirm the git side is in sync first -- cheap and catches the common case:
   `git log --oneline -1` locally should show:

   If it doesn't match, `git pull` first before checking data.

2. From the LOCAL repo root, run the exact same three commands used to
   build this manifest, and diff:

   ```bash
   find models -type f -printf '%s\t%P\n' | sort -k2 > /tmp/local_models.txt
   find outputs/metrics -type f -printf '%s\t%P\n' | sort -k2 > /tmp/local_metrics.txt
   find outputs/optuna_studies -type f -printf '%s\t%P\n' | sort -k2 > /tmp/local_optuna.txt
   ```

   Then compare each against the matching section below (copy each section
   of this file, minus the `models (...)`/`outputs/...` header line, into
   a file and `diff -u <that file> /tmp/local_*.txt`). A clean diff means
   byte-size-identical file sets -- not a checksum, but sufficient to catch
   missing/truncated/extra files, which is the realistic failure mode for a
   manual copy.

3. Report back: any path present here but missing locally (dropped during
